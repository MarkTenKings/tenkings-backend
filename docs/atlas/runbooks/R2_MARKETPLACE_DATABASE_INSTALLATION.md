## Confirmed managed-role incompatibility

Current protected catalog validation rejects **any** `pg_auth_members` edge touching `atlas_marketplace_owner`, `atlas_marketplace_writer`, `atlas_proof_retention_writer` or `atlas_proof_intake_writer`, in either direction. Incoming ADMIN-only membership is rejected even when INHERIT and SET are false. The saved managed-cluster metadata already shows `doadmin` has grantor-`postgres` ADMIN memberships on existing R1 managed roles, including `atlas_comp_curation_r1`.

PostgreSQL17 automatically grants a newly created role back to a non-superuser creator with ADMIN enabled, INHERIT/SET disabled, and the bootstrap superuser as grantor. The creator cannot remove or change that grant. ADMIN also permits the administrator to issue additional membership grants, so disabled inheritance/SET are accident safeguards rather than isolation from that administrator. See [PostgreSQL17 role attributes](https://www.postgresql.org/docs/17/role-attributes.html). [DigitalOcean's privilege documentation](https://docs.digitalocean.com/products/databases/postgresql/how-to/modify-user-privileges/) confirms managed customers do not receive superuser access.

Consequently the proposed `doadmin` installation cannot meet the unchanged zero-membership contract. This is a supported incompatibility, not a hypothesis requiring a production role experiment. Do not run the prepared target preflight merely to rediscover it, attempt to revoke the bootstrap grant, or create the target database/roles before resolving the engineering choice below. Existing source guards and validators remain unchanged.

Non-superuser ownership transfer remains a separate installation detail if the managed option is selected. Any additional temporary SET-role membership or database CREATE grant used to transfer schema/functions/tables and set owner defaults must be removed afterward. The bootstrap ADMIN-only grant is the permanent exception under consideration; temporary INHERIT/SET grants are not included. The NOLOGIN function owner must not own the database or retain database CREATE/TEMP. Provider mandatory defaults or extra executable functions still must meet the existing fixed checks.
