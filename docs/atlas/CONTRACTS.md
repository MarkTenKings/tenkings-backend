## Authority

| Actor | Permitted | Authority retained elsewhere |
|---|---|---|
| Astra machine | Assigned evidence reads/crops; identity, geometry, finding and missed-defect proposals; bounded sold research; deterministic previews; draft review submission | No certificate, publication, trusted lesson, map activation, price confirmation, purchasing or buyback |
| Deterministic adapters | Preserve/verify bytes; transform/crop/segment/measure; calculate grade and money; render; validate receipts; transact state | Cannot create human approval from a schema or a successful model answer |
| Trained human | Approve identity/findings and exact report revision; separately approve specified trusted lessons | Cannot erase raw findings or prior decisions; changed evidence invalidates approval |
| Issuance adapter (unimplemented) | Consume fresh exact human certification authority in existing atomic issuance transaction | No machine route, generic admin proxy or certificate allocation in draft rendering |

Machine claims have `audience=atlas-machine`, subject, exact card/specimen/run/evidence/manifest, allowed tools and bounded validity. Middleware must authenticate the caller and derive these claims; the model never supplies a role/actor/tenant/credential. The local context objects are injected synthetic assertions, not signed tokens. Real staff authentication, roster checks, training authority, token mint/verify, revocation, CSRF and assignments are still integration work. Machine and staff credentials must be distinct; no shared DB/admin bearer or current human rescue/completion route is allowed.

Every tool argument binds `operationId`, `cardId`, `runId`, `expectedRevision`, `evidenceHash` and `runManifestHash`. Strict parsing rejects unknown keys, unsafe/nonfinite numbers, unsupported types and excessive bytes. Operation identity is server-controlled or validated within the run. Duplicate exact payload returns the committed result; same key with changed payload is a conflict. Invalid calls count toward the local action budget. `reconcileMachineOperation` is a separate read-only executor seam for a lost reply after caps/deadlines; it requires a current scoped capability and cannot create work.

Fourteen schemas are exported in `MACHINE_TOOLS`. The local dispatcher implements evidence read, append-only identity/geometry/finding proposals and exact draft submission. Other tools return `ADAPTER_REQUIRED`—never a fabricated success. The declared geometry, SAM, comps, valuation and rendering tools need their reviewed deterministic/broker adapters before operation. This avoids duplicating the current grading formulas while their owner repairs them.

All IDs resolve from the assigned manifest. No tool accepts a URL, storage key, SQL, arbitrary provider request, shell command, human role, grade, millimeters, certificate number or confirmed market value. `summary` and marketplace text remain untrusted data; they are neither runtime instructions nor report facts. Provider text cannot change the capability, tool inventory, budget or frozen policy. Rendering must escape text and use only material facts linked to approved receipts; that renderer is not implemented here.

## Evidence and immutable review

One specimen identifies a physical card, independently of its catalog identity or photograph hash. Exactly one Front and Back original are preserved with hashes, dimensions and side. Source/crop/derived lineage carries source hash, rectangle and transform hash. Crop coordinates are nonempty integer source pixels, bounded to the exact source, with no caller-supplied transform. Geometry citations must refer to that same side and source. Raw detected and suppressed findings, original masks and filter reasons remain intact; proposals cannot replace the ledger. Existing finding IDs are required except for an explicit ADD with a source-bound mask.

The offline crop-recording seam trusts a synthetic deterministic adapter for actual cropping, decoding/dimensions and request delivery. It hashes supplied bytes and validates coordinates, but does not prove those bytes are the specified optical crop. Production must decode/hash exact authorized originals, generate deterministic crops, verify dimensions/transforms, bind the actual request image roster and response ID, and record which regions were delivered for inspection. Complete rectangle union is calculated without counting overlaps twice. Delivery coverage is explicitly **not proof the model visually inspected or correctly understood a region**. Overview delivery cannot certify faint-defect recall; targeted-resolution coverage and human truth are separate evaluation gates.

Each material proposal, human override and rendered package creates a fresh immutable revision. History retains full prior proposals/overrides/receipts/packages. Full prior human approval receipts also remain append-only after edits. The revision hash includes the exact evidence, frozen run manifest, proposals, overrides, deterministic receipts and package hashes. Raw evidence is never rewritten. A same-grade new revision still requires a new approval.

The synthetic package receipt binds identity, geometry, detection, grading, renderer, report, label, complete raw finding IDs and delivered-region roster. All six prerequisite receipts are required. Comps/NFC/presentation remain optional and cannot fabricate values or block mathematical validity. Package creation yields `DRAFT_NO_CERTIFICATE`. Production receipts must additionally verify real signatures, source bytes, measurements and deterministic output; the `SYNTHETIC_ADAPTER` mode deliberately proves none of those live facts.

Human approval requires the currently trained/fresh staff identity, exact card assignment fence, unexpired assignment, revision hash, evidence/manifest and package hash. `approvalMatches` checks the exact stored issued mock receipt and all scope fields. A digest is content integrity, not human authentication. Certification and trusted-learning approval have distinct purposes. No trusted-learning approval function is implemented; certification review receipts carry no approved lesson IDs. Future learning approval must name exact lesson IDs/source revisions and independently revalidate human authority.

## States and durable adapter contract

The executable proposed stage matrix is `src/states.mjs`:

`PAIRED_INTAKE → EVIDENCE_VERIFIED → IDENTITY_PROPOSED → GEOMETRY_VALIDATED_FOR_DRAFT → DETECTION_COMPLETE → AI_REVIEW_PROPOSALS → DRAFT_PACKAGE_READY → READY_FOR_HUMAN → HUMAN_REVIEW → HUMAN_APPROVED`.

Only a future trusted issuance transaction may move approved work to `CERTIFIED`. It must recheck current human roster/freshness, exact approval/revision/source, and idempotent existing session/label/card identity under locks. It commits issuance linkage and outbox once or none; external email/storage/research do not occur inside that transaction. Existing issued identities and Ten Kings ownership rules cannot be silently reused for a different ATLAS issuer. That policy is unresolved, so this package allocates no certificate or permanent card.

The local reference implements proposal/checklist/review transitions, not every optical stage. Identity/geometry/detection stages are represented by bound synthetic prerequisite receipts. `NEEDS_IDENTITY`, `NEEDS_CAPTURE`, `NEEDS_EXPERT`, `RETRY_WAIT`, `UNKNOWN_PENDING_RECONCILIATION`, `QUARANTINED` and `DEAD_LETTER` are explicit planned exceptions. They preserve evidence and require a named resume/reanalysis decision; no fallback worker/model/bank is selected.

The production persistence design is one job/step ledger plus transactional outbox in the existing Postgres boundary, subject to shared-schema coordination. No migrations or new queue service are created here. Required constraints are unique run/specimen binding; unique `(run, operation)` frozen input identity; distinct provider attempts; monotonically increasing lease fence; immutable revision/approval records; and unique outbox logical event identity. Use transaction locks/CAS for counters and current revision. The local file store demonstrates the transaction semantics without claiming database isolation.

Lease claim/renew/output commit require current owner/fence, expiry, revision and run manifest. A takeover marks outstanding dispatched attempts unknown. Output, its hash, actual cost, reservation settlement, terminal/retry state, audit event and outbox insertion commit together. A stale worker cannot renew or publish results. A new authorized lease may reconcile an older paid attempt: costs remain recorded even when stale output is dead-lettered. RESERVED work can be reclaimed without dispatch duplication; DISPATCHED work is never blindly resent.

The local file adapter uses create-exclusive lock, write/fsync, atomic rename and directory fsync. Interrupted-before-rename leaves the prior transaction; interrupted-after-rename replays its stored outcome. Tests simulate those failpoints and reopen the file. They are not OS power-loss/process-kill or distributed-database tests. A lock left by a killed process stops with `STORE_BUSY_OR_RECOVERY_REQUIRED`; remove it only after proving that process stopped. Corrupt envelopes fail closed. The future DB adapter needs real kill/concurrency/restore/second-deploy tests before any operational use.

Outbox delivery is at least once: consumers must deduplicate the event ID and revalidate revision/type before an effect. ACK is idempotent against the exact payload. The reference has no delivery loop or issuance consumer. Production needs fenced publisher claims, retry scheduling, delivery attempts and DLQ visibility. A missed ACK must never duplicate a certificate or financial effect. Dead letters retain the request/output/evidence/cost/reason; explicit reviewed replay is a new bounded attempt or analysis revision, never clearing history.

## Deadlines, spend and resumption

Server policy caps batch/card micro-USD, provider attempts per card, three attempts maximum per logical stage, tool calls, stage/card/night duration, lease duration and output/image/JSON sizes. Reserve the full approved worst-case request envelope **before dispatch** against both card and batch totals. Local retries honor Retry-After and bounded exponential jitter. Authentication, funding, wrong release, policy drift and invalid inputs are terminal/pause conditions, not ordinary retry exhaustion. A real adapter must map actual provider error codes into these classes; mock status strings do not implement provider classification.

Unknown request outcome or absent usage keeps the reservation held and requires reconciliation. No automatic resend, zero-cost assumption or reservation release is allowed. A measured cost exceeding its reservation is retained and pauses admission. Input/provider/manifest/revision/reservation identity is fixed across retries. SDK retries must be disabled in a live adapter so this ledger owns every request. Admission also needs actual per-provider RPM/TPM/image/concurrency limits and funds/availability; these are deliberately unmeasured and unconfigured here.

After pause/deadline and lease expiry, a trusted executor may claim `RECONCILE_ONLY` for already pending attempts. This lease cannot reserve or dispatch work; it can record verified charges and preserve/dead-letter the result. An undispatched RESERVED attempt can release its reservation only through explicit reconciled terminal-zero accounting. This prevents both stranded bills and a recovery path that silently spends more.

Freeze model alias/returned identity, effort, full instruction/prompt hash, strict tool schemas, grading rules, map revision, approved Memory snapshot, worker release/checkpoint/GPU/determinism policy, capture policy, renderer and pricing policy. A changed manifest creates a newly reviewed analysis revision; no partial resume may quietly use new policy. Old captured/human sessions remain historical evidence; they cannot be imported as current ATLAS worker proof merely because a legacy reader accepts them.

## Responses integration verified against official documentation

The request builder emits `model: "gpt-6-astra"`, `reasoning.effort` (offline candidate medium), `service_tier: "default"`, `store: false`, `parallel_tool_calls: false`, bounded `max_output_tokens`, instructions, input items and closed strict functions. No temperature/top_p/logprobs, Chat Completions tooling or model substitution is used. Engineering tasks use Max at Mark's request; API effort must be benchmarked independently. Astra supports low/medium/high/xhigh/max and currently lists only the undated alias as its snapshot. [Astra model](https://developers.openai.com/api/docs/models/gpt-6-astra), [function calling](https://developers.openai.com/api/docs/guides/function-calling).

Strictness controls structure, then application checks control authority and semantic joins. Refusal, incomplete/failed output, unexpected tools/model, call-ID mismatch and oversized responses produce explicit non-success. Exact tool outputs match `call_id`; stateless continuation preserves every response output item, including opaque encrypted reasoning. We neither inspect it as an explanation nor request private reasoning. Current documentation says encrypted content is included by default with `store:false`; no legacy include field is necessary. [Reasoning continuation](https://developers.openai.com/api/docs/guides/reasoning#preserve-reasoning-without-stored-responses).

The builder emits hash-verified synthetic PNG data URLs with `detail:auto`. Real image adapters must enforce exact object access and data minimization. Astra's actual detail/resizing/token behavior is unmeasured; the fetched generic model sizing table omits Astra. No other model's image multiplier is used. The initial paid preflight must measure detail support, crop coordinate behavior, image/input/output/reasoning/cache usage, latency, quota and payload errors. [Image inputs](https://developers.openai.com/api/docs/guides/images-vision#model-sizing-behavior).

Token accounting preserves provider usage and estimates all input at a supplied conservative ceiling with output including reasoning once. Prices and actual invoices must be separately pinned/reconciled; synthetic fixture amounts are not a business quote. `store:false` does not itself mean Zero Data Retention. Files/Batch/background modes have distinct retention/operations and are outside this initial adapter. [Data controls](https://developers.openai.com/api/docs/guides/your-data).

There is no paid API client in this package. Operational integration needs the separately approved capped pilot, dedicated project/key, quotas, current worker proof, reviewed retention policy, authenticated capabilities, real deterministic adapters and durable persistence. Mocks authorize none of those actions.
