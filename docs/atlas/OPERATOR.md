# ATLAS Astra operator implementation

The production runner is being implemented in `packages/atlas-operator`, separately from the earlier offline reference package. The Responses transport now has a real PostgreSQL dispatch ledger, restricted machine credentials and immutable run/attempt/receipt/step/outbox records. There is no activated production runner, scheduler or credential. Concrete report/crop/proposal adapters, machine initial grading, operator reconciliation and human proposal review remain required before live use.

The initial contract defines ATLAS tools for report/evidence reads, exact image crops, identity/finding proposals and submission to the human queue. The runner may advertise a tool only when its adapter is implemented and admitted. It never exposes report approval, publication, training, map activation, generic browsing/shell or money actions. Tool calls bind a run, evidence hash, manifest and revision. Scores and measurements continue to come from the existing ATLAS engine. Optional catalog/comps tools are not advertised before their adapters are implemented and admitted.

Current official API verification (September 8, 2026): [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) uses the exact `gpt-6-astra` identity with an explicitly frozen supported reasoning effort. [Strict function calling](https://developers.openai.com/api/docs/guides/function-calling#strict-mode) requires every object to reject additional properties and every field to be required; nullable fields express unknown values. Requests use Responses, `store:false`, one tool at a time, disabled truncation and bounded output. [Stateless continuation](https://developers.openai.com/api/docs/guides/reasoning#preserve-reasoning-without-stored-responses) preserves every output item, including opaque encrypted reasoning, and matches tool results by call ID. Opaque content is never decoded or presented as an explanation.

The transport has one fixed endpoint, dedicated ATLAS project/key variables, no automatic SDK retries or redirect, a bounded response/time limit and a client request ID equal to its durable attempt UUID. The ledger consumes dispatch authority before the transport sends anything. Network uncertainty, malformed responses and missing usage never become a zero-cost success. HTTP error receipts retain their status/request ID and Retry-After for reconciliation; the transport does not automatically retry them.

Budgeting uses the documented 922,000-token maximum input envelope until an admitted preflight establishes a tighter enforceable bound. The current [Standard pricing table](https://developers.openai.com/api/docs/pricing) has a maximum long-context input/cache-write rate of $25 per million and long-context output of $75 per million. Each request reserves that conservative input envelope plus its configured maximum output. With 2,000 output tokens this reserves $23.20 temporarily; this is a ceiling, not an estimate of normal card cost or permission to spend. Actual returned token usage can establish a conservative accounting ceiling at the same pinned rates; output already includes reasoning tokens. Invoice charges and usage ceilings remain distinct records. Quotas, spend approval, retention/account policy and current provider access must still be verified before live execution. No regional, Fast, Batch or alternate model fallback is permitted by this initial transport.

## Durable job boundary

The sixth additive staff migration stores each run's original policy bytes, runtime hash, evidence/analysis/review heads, asset manifest and bounded conversation. Current activation, ten present specimens, shared grading admission and deadlines are checked under the same short database lock used by human grading. The initial admission requires this pilot's newly committed INITIALIZE result; the runner cannot import a historical cached grade or create a human identity. Elevated intake creates runs. `operatorGrantSQL` provides the separate runtime role with exact table/column/function privileges, verified on every transaction. It cannot change controls, evidence, training, actual invoice cost or public reports.

Leases last at most 60 seconds, with explicit owner/fence and a one-run concurrency limit. A reserved but undispatched claim can be cancelled after expiry; it contributes no provider cost and can never dispatch later. A consumed or uncertain claim recovers only into reconciliation mode. UNKNOWN runs cannot return to ordinary processing. Receipts persist before tool execution, including after lease expiry, revocation or policy amendment. Duplicate receipts are idempotent; conflicting receipts remain retained and stop further tools. Usage accounting is checked against the original run policy and immutable response, and actual invoice evidence is separately write-once. The shared pilot budget sums both the existing grading worker and Astra, including held uncertainty and observed overruns.

Each applied tool atomically commits its exact request, result, continuation hash and next run revision. Submission binds the current report hash and an immutable outbox entry in the same transaction; it never creates human approval. Outbox delivery uses expiring fenced claims and exact-payload idempotent acknowledgement. No external notification has been sent. Human saves, regrading and approval are blocked while machine work remains unresolved.

Local acceptance: 60 actual PostgreSQL scenarios (47 previous + 13 operator) on all 93 unchanged public and six additive staff migrations, with unchanged second-deploy ledgers and owned cleanup. Evidence: `/private/tmp/atlas-staff-db-XJkpEX/result.json`. Provider responses, illustrated cards and tool adapters in these tests are synthetic. The tests establish persistence/concurrency/authority behavior, not Astra's card inspection quality. Production-grade crop delivery, proposal decisions, operational recovery and a supervised ten-card evaluation still need to be completed.

## Image renderer and continuation

The pure private image renderer now produces exact native crops or bounded full-side overviews from supplied preserved bytes. It verifies the source hash, dimensions, type and container; uses explicit EXIF-oriented coordinates; and emits sRGB PNG without annotations or metadata. Packets bind the exact run/evidence/manifest, asset, rectangle, transform, decoder and output bytes. The locked application decoder is Sharp 0.33.5/libvips 8.15.3. A bounded PNG chunk walk rejects APNG explicitly because this decoder silently reads only its default frame. Seven pixel/admission tests include manual source-pixel mapping, EXIF orientation, truncation, animation and packet substitution. A fresh independent High review found the APNG case; the lead fixed it and added the valid two-frame regression.

Responses continuation can include validated PNG image content in tool outputs while preserving exact call IDs and opaque reasoning items. The operator/bridge suite passes 24 tests. This renderer and wire validator do not themselves authenticate storage access or establish current job/lease authority. The machine bridge, durable image delivery roster and runner integration remain required; no live multimodal provider call has been made.
