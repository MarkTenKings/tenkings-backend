## Implemented improvements

- **One Save & Review Geometry action** validates identity inline, saves dirty details, then initializes using the acknowledged revision. Existing pending requests remain resumable with the same action identity; newer local edits and stale-response guards are preserved.
- **Front and Back uploads can overlap**, each with independent progress, errors and recovery. A synchronous same-side lock prevents duplicates. Out-of-order completions cannot roll back newer state. A fresh, unambiguous upload plan skips one guaranteed-absent completion probe; recovered or uncertain operations still reconcile before any PUT.
- **Stage navigation responds immediately** while a shared background image-grant refresh runs. Unsaved edits, pending saves, required geometry confirmation and exact revision/hash bindings still gate dependent work.
- **Repeated read work is removed:** the representative paired-image descriptor path falls from 41 to 6 authenticated database transactions and from 16 to 4 photo-source/prepared-manifest artifact reads, with all 12 image grants retained. Reuse is request-local; final authorization/current-pair checks and cold byte verification remain. Independent reads run in bounded parallel branches. Unchanged, already-verified geometry/defect artifacts reuse their immutable references; changed artifacts still receive write/readback verification.
