# Private ownership evidence and reviewer authority — local proposal

This source increment is disabled, unregistered and unexposed. It extends the previously qualified ownership writer with retained private evidence and named independent reviewer authority. It does not establish ownership for any real card, provision a reviewer, register a migration or change production.

The new SQL stores bounded immutable PNG/JPEG bytes, server-computed hashes, an evidence manifest and exact ownership-event links. A manifest hash is assigned unconditionally by a server trigger. Hash equality proves byte integrity, not authenticity or legal ownership. Evidence downloads are private attachment-only octet streams with nosniff and sandbox policy; no public URL or inline active content is introduced.

Policy starts disabled with no accepted proof kinds. Reviewer grants bind actual staff/customer identity versions, existing authority and exact expiry. Self-review, missing/revoked authority and wrong-card access refuse. The restricted serving role has only the dedicated customer/reviewer gateways. An internal transaction/PID-bound guard prevents an accidental grant to the older mutator from bypassing evidence. Authority, policy, evidence and locks are checked again before an ownership event; reads never establish title.

## Required before operational activation

Accepted proof categories, linkage/review rubric, escalation and actual named reviewers remain unspecified. Retention expiry denies use; it does not delete bytes or define backups/legal holds. The native64KiB byte cap does not fit the existing32KiB JSON request limit after base64 expansion; no request limit has been widened and useful legible-proof transport remains to be designed. PNG/JPEG signature checks alone do not validate proof content, and PDF/HEIC are unsupported.

Pending claims can become unreviewable after evidence expiry or policy revision, while the original writer still blocks a second pending claim. Withdrawal, replacement and policy rollover need an append-only lifecycle successor before enablement. Current source must not silently mark these claims rejected or revoke established ownership. Authenticated customer/reviewer status readers are the next local increment. Collection persistence, customer provenance, transfer consent, disputes/reholder continuity and completeR1 remain unfinished.
