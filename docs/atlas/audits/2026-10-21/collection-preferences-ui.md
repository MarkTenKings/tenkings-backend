# Optional collection settings UI — local qualification

The new `CollectionPreferences` panel is an explicit, default-absent composition in `CollectionWorkspace`/`MyCollection`. It receives the existing bootstrap customer/CSRF object and a supplied preference transport. It adds no route, runtime, SQL, credentials, provider, grading, or production activation.

The account panel offers Private/Public visibility and an offer opt-out for all cards. Each card has a separate, initially closed settings panel with its own visibility/offer opt-out. Copy states that these are saved preferences: public collection browsing and offer delivery are unavailable. The existing approved photograph/report and ownership meaning stay unchanged.

## Save and access behavior

- Current settings, the requested change, and the last confirmed request receipt have separate labels. The requested choices remain visible and disabled during an unconfirmed save; an older receipt never becomes proof of current settings.
- Unknown outcomes expose only explicit request lookup or retry of the same immutable request. An absent lookup/generic conflict does not enable a new save. The exact typed strictly-monotone stale witness requires an explicit current read before another chosen save.
- Saving/reloading one panel never reloads the parent collection. A card draft or uncertain request survives an account save; photograph reads remain stable. Filtering/page navigation can dispose forms, with a notice that an unconfirmed save may still have recorded.
- Captured customer object/ID, session/CSRF, transport, card, access and generation fence render and asynchronous callbacks. Pure checks hide old values before effects; disposal happens in lifecycle/events. StrictMode replay creates a fresh controller without reviving a permanent access-ended state. Authoritative denial ends the captured parent page; an old page's denial cannot clear its successor.
