## Capability and authority

The new `atlas_ownership_preferences.customer_call(text,text,jsonb,text,jsonb)` exposes only live access/current preferences/current owned card reads, collection/card preference writes, and exact own-request recovery. A distinct serving role receives schema USAGE and EXECUTE on this sole security-definer gateway. It receives no original combined ownership gateway, helper, table or sequence access. The gateway preserves the original cookie proofs, five-field customer-control binding, account serialization and existing preference branches; original ownership/auth schemas stay byte-identical.

The service validates exact role identity, membership/ownership, effective database/schema/table/column/sequence/custom-routine rights and reviewed dependency bodies before and after each transaction. It rejects PostgreSQL17 MAINTAIN and database ownership as well as ordinary table privileges. Review-pinned function owners, security-definer flags and search paths are required. The service uses a caller-owned distinct client and performs no construction/import I/O; close invalidates its capability without disconnecting that caller client.

Live current_account checks surround waits and responses. Current card reads lock the original card, permanent report identity and intake source in the existing order, then obtain the current owner's published-card projection. An account or source/capability rejection after an inserted preference event must throw inside the transaction. SQL final expiry uses RAISE so it rolls back the nested write; JavaScript projection, role and final live-access failures also throw before commit. A failure after commit remains an unknown outcome.

## Closed contract

Actions are `read_access({})`, `read_preferences({})`, `read_card({cardId})`, `recover_request({requestId})`, `set_collection_preferences({requestId,expectedPreferenceRevision,visibility,offersDisabled})`, and `set_card_preferences({requestId,cardId,expectedOwnershipRevision,expectedPreferenceRevision,visibility,offersDisabled})`. UUIDs, integer bounds, exact fields, data properties and types are validated in both SQL and JavaScript. No caller account ID is authority. Projections are bound to the independently authenticated access response.

Current settings use `atlas-ownership-preferences-current-v1`; account-wide and card preference revisions remain separate from ownership revision. Collection defaults to PRIVATE, while the offers preference defaults to OPEN_TO_OFFERS. Each explicit collection/card disable persists independently. Effective visibility and opt-outs do not create a listing, receive an offer or claim notification delivery: `canReceiveOffers:false` and `notificationDelivery:NOT_REQUESTED` remain explicit.

Historical results use `atlas-ownership-preferences-receipt-v1`, with RECORDED/ABSENT and exact account/request/action/input/event/card/stored revision/time. They do not graft current settings onto an old receipt. Same-account same-input replay returns the original receipt after transfer/discard; a new write still requires current ownership/source/revisions. Recovery never exposes competing identities or non-preference request details. ABSENT describes that read instant and is not proof a delayed request cannot arrive later. Callers must retain the original immutable request through unknown outcomes, read that exact request, and only explicitly retry the same request; current equal-looking values or generic HTTP failures are not receipt proof.

SQL emits canonical UTC timestamps and the service sets transaction-local UTC, independently of session defaults. Original writer SHA256 remains `00720728d42a1276d50c70998d22e9e309cec2b1bb5cdd9ba8c7126e16fc36a2`.
