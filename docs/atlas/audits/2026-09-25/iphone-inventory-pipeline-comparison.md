# iPhone Inventory / ATLAS pipeline comparison

September 25, 2026 UTC. ATLAS-only investigation and bounded implementation; no Ten Kings changes, production/provider mutations, model calls or grading approval.

## Finding

Inventory's speed cannot be copied by uploading its smaller JPEGs as ATLAS grading originals. Its browser deliberately normalizes every capture/import to a 1,400-pixel JPEG; ATLAS retains native originals or every delivered video-frame pixel. ATLAS already uses direct signed object uploads and a small identification derivative. The reusable lesson is independent capture/upload/processing with bounded retries and no unnecessary image reads, while preserving exact grading evidence.

The supplied diagnostic records 12 pairs: six marked upload-complete, six pending with 12 retained photo references totaling 74,370,722 bytes, plus a partial Front. Ordinal 6 has `PHOTO_HDR_UNSUPPORTED`; 8/9 have `BATCH_IMPORT_INTERRUPTED` without a recorded phase. The diagnostic does not prove unreadability, quota exhaustion, all-card grading completion, or 50 simultaneous jobs. The separate exact-original investigation reproduced an overly broad primary-XMP rejection on ordinary iPhone metadata for all three verified Front originals that lacked prepared source (ordinals 6, 7 and 12). Browser retry/scheduling, JPEG admission and action-conflict corrections are owned by the other specialists.

## Measured full-resolution cost and bounded fix

Offline exact-original decode/derive on this Mac (Node 25.6.1, arm64), using the companion JPEG correction:

| Original | Original bytes | Oriented pixels | Each decoded / working PNG | Decode + working conversion |
| --- | ---: | --- | ---: | ---: |
| Ordinal 6 Front | 6,256,391 | 3024×4032 | 23,432,825 | 608ms + 546ms |
| Ordinal 7 Front | 6,670,634 | 3024×4032 | 24,763,698 | 623ms + 618ms |

Original hashes remained unchanged. Both originals are 4032×3024 with EXIF orientation 6; the oriented raster has 12,192,768 pixels and 36,578,304 RGB bytes. A same-aspect 1,400px Inventory image has 1,470,000 pixels, about 8.3× fewer. These exact samples' decoded and working PNG bytes are equal, but their source/working descriptors represent distinct evidence roles; this patch does not merge or remove those objects. These are local measurements, not deployed Linux or iPhone throughput claims. [Timing receipt](../../../../validation/atlas-iphone-pipeline-20260925/offline-native-timing.json).

The avoidable cost found with the parent investigator was background batch calls to `connected.open()` generating display preview URLs. `frontend/atlas-app/lib/server/connected-manual-runtime.mjs:70` resolves those via `createDecodedFrameRead`; `packages/atlas-photo-storage/src/index.mjs:200` first calls `readExpected`, whose `:129` HEAD + GET reads/hashes the entire PNG. The batch worker never uses the returned previews. A cold read can therefore fetch roughly 23–25MB per side solely to create unused URLs and can fail with `PHOTO_STORAGE_UNAVAILABLE` before useful batch work. The runtime has a 240-second descriptor cache, so this is a cold/expired-cache cost, not a claim that every repeated open downloads again. This is a concrete avoidable failure path; it does not by itself identify the historical cause of every storage failure.

Implemented only in ATLAS: the existing card reader moved unchanged into private `src/card-reader.mjs`, with an internal `includePreviews` option. Only exact `false` disables preview reads. Batch preparation requests that option; normal interactive opens still include both previews. All intake/details/manual/identification/geometry reads and the final source/revision check remain. Batch still requires the same source hash and exact Front/Back upload IDs. Original storage, dimensions, decoding, inference, scoring and approval are untouched.

Validation: focused reader + batch tests passed 16/16. They exercise the production reader with a failing preview provider, verify ordinary UI behavior and strict opt-out, retained initial/final authorization and source/revision fences, and actual batch preparation rejecting mismatched source/upload identities. An expanded targeted run passed 72 tests; its composition test could not load the absent local `@tenkings/ebay-sold-comps-v2/dist/index.js` build prerequisite. Final isolated release qualification must build that existing dependency. This audit makes no deployment or physical-iPhone acceptance claim.
