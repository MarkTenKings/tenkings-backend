## Transparent preview cache and cold access behavior

The native reader now optionally creates an immutable private WebP display derivative for any verified saved inspection source, including historical approvals. Its key binds source SHA and the complete recipe/Sharp native encoder identity. The source bytes/hash/length/dimensions are verified; conditional create-only writes converge across concurrent processes without changing saved approval/media/report records. Cached bytes, metadata and dimensions are checked before signing a fresh120-second browser-compatible URL. No signedURL or access decision is cached, and the reader still rechecks publication authority before returning the response.

Work is bounded to one active job/eight admitted unique jobs per process, an8-second shared deadline,50MiB canonical source limit and1MiB output limit. A credential-free Sharp child owns the native resize; cancellation kills the child and releases the CPU slot only after exit. Caller cancellation does not cancel another coalesced caller’s work. The native source closure includes all three modules and existing Sharp0.33.5. Cache/reader tests pass34/34 under Node22, including real SDK signature-header compatibility, corruption, conditional races, caller cancellation, queue/deadline limits and publication revocation. Independent packaging/runtime tests pass16/16.

Primary image access waits at most250ms for this optional derivative. A cold/slow cache returns the saved verified JPEG with `alphaPreviewPending:true`; the browser keeps that photograph visible while making at most three lower-priority, source-bound alpha-only rechecks (nominally2/5/9seconds, plus request time). Rechecks never download the JPEG or large original again. On success, the verified transparent preview replaces it automatically; expiry, corruption, source changes, navigation and access loss cannot publish late or unbound bytes. Persistent optional failure retains the verified fallback and can therefore retain the old pale JPEG fringe; no universal instantaneous-loading claim is made. The loopback cold-cache control exercises the visible automatic replacement rather than only the always-warm path.
