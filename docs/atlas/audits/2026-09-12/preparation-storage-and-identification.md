## Native HEIC boundary

[`@atlas/photo-runtime`](../../../../packages/atlas-photo-runtime/README.md) now
has a pinned libheif1.23.2/libde2651.1.1 Node-API adapter inside its disposable
decoder child. It selects the actual primary still item, including second-primary
collections, and decodes verified direct HEVC or uniform HEVC grids at8/10/12 bits.
Exact tile/canvas coverage, item-local property associations and color/depth
agreement are checked. The separate PNG encoder applies supported crop/orientation
once and preserves every decoded high-depth value in16-bit output.

Qualified direct orientations and even-grid transformations match independent
integer permutations and native default decoding. That comparison exposed an
odd-grid transform difference; nonidentity transformations of odd grids are now
explicitly refused. An earlier property-index mismatch was corrected by parsing
`ipma`: libheif property IDs are local to the item's association list, not global
container-property indices.

Independent review then found odd-origin crops could succeed with different
native-default pixels in both direct and grid images, and composed-identity
mirror/rotation sequences could bypass the odd-grid guard. The final boundary
requires even crop origins for both types; any raw nontrivial transform also
requires even source/effective crop dimensions. Repeated rotation or mirror
properties are refused as unqualified complex sequences. Regression tests retain
the counterexamples. Full odd-grid identity remains supported when its crop is
otherwise qualified. No failed pixel comparison is presented as a passing one.

ICC-free matched NCLX BT.709 primaries/sRGB transfer in the tested matrix subset
produce tagged sRGB. Unprofiled inputs remain unmanaged with null color space and
unknown dynamic range. All associated Exif metadata, ICC/wider color, HDR/gain
maps/alpha/auxiliaries, separately transformed tiles and unsupported geometry are
refused. **This does not yet support general native iPhone intake.** Those phones
can supply precisely the metadata/color forms not yet qualified. The earlier
CPU preparation adapter also refuses unmanaged and16-bit output; decoder support
alone does not complete original-quality grading.

The native adapter pins codec versions, preserves built-in security limits and
adds per-image bounds. Actual repeated HEVC decoding is killed and reaped in the
cancellation tests. The local compiler/build receipt binds source and binary;
generated binaries/shared libraries must be explicitly packaged for the eventual
deployment. No npm dependency was added, global installation performed or Linux
native build claimed. Native memory still requires outer process limits.
