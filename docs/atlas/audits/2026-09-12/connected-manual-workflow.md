## What is connected

The actual dedicated staff app now has a feature-gated manual card list and
native Front/Back intake, automatic shared-engine eight-field suggestions,
durable corrections, paired geometry/defect tools and separate exact report
approval. The staff app remains on the approved Vercel `/admin` architecture;
new native work runs in a separate private Linux service. The new card routes
carry signed method/path/body/cookie/CSRF/origin/timestamp/nonce evidence and
reauthenticate ordinary staff access on the private side. The web artifact
contains only the new signed transport and browser clients, not native CPU code.

Native upload plans are independent per side/version. The browser retains the
exact Blob and upload identity across interrupted transfers; completed originals
are verified before preparation. Definite pre-plan refusals can be discarded
without abandoning an uncertain grant, verified local copies can be cleared,
and original size is checked before reading/hashing. There is no product card
allowance or old operator cohort dependency in the new manual intake.

Each original remains immutable alongside a rich decoded primary and separate
full-resolution sRGB RGB8 SDR working PNG. Apple's qualified P3 HDR-gain-map
container is admitted only with the explicit owner-approved SDR-base policy.
The original still truthfully records HDR data; gain-map rendering is not claimed.
No spatial resampling occurs in SDR conversion. Preparation and grading retain
the existing card/inspection grids and scoring. Physical optical acceptance is
still a human task.

Shared identification preserves the extracted Ten Kings prompts, field meanings
and request/model settings. One unique claim per current photo pair gates two
OCR requests and one identifier request. Exact immutable request/reply artifacts,
usage and uncertain dispatches are retained. Suggestions cannot overwrite touched
human fields. A narrow SQL receipt append can preserve a matching late reply after
staff expiry without authorizing result adoption, a new request or report approval.
Post-initialization identity edits belong to the manual report workflow.

CPU/storage operations run outside short per-card transactions. Source and detail
checks are repeated at actual commit. Front replacement preserves exact unchanged
Back geometry, findings, inspection and preparation. An approval racing a source
replacement cannot commit; earlier approved snapshots remain immutable history.
Saved defect candidates survive measurement failure, and recovery reuses the
exact pending action. Both sides must be inspected before the single Confirm
findings action; final trained-human approval is separate.

Full-resolution image bytes bypass the Vercel response cap through short private
object grants. Before review display, the browser checks streamed size, optional
expected byte count and SHA-256, then creates a Blob without reencoding. Expiring
URLs are excluded from pixel lineage, so renewal does not itself erase edits.
Stale fetches are cancelled and replaced/unmounted Blobs are revoked.
