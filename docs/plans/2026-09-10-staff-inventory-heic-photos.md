# Staff inventory phone photo preparation — September 10, 2026

Mark requests HEIC/HEIF iPhone uploads and direct camera entry in the existing staff inventory workspace. This scoped implementation prepares descriptive inventory photos locally in the browser, preserving the existing authenticated endpoint, private object storage, byte validation, metadata stripping and checksum verification. It changes no grading photograph, inventory journal, database schema or business fact. The release coordinator owns integration and deployment; this assignment performs no production upload, database write, commit or deployment.

Add one reusable browser preparation helper shared by Add and Edit. Recognize actual JPEG, PNG, WebP and HEIC/HEIF bytes, bound source files to 30 MiB and still images to 50 megapixels, use the browser's native photo decoder where available, and load a pinned libheif-js 1.23.2 browser worker only when HEIC requires it. The worker is disposable and has a bounded timeout. Use the actual primary still image and its container orientation; no remote conversion service receives source photos. Draw the oriented image inside 1400 × 1400 without cropping or enlargement, flatten transparent backgrounds to white, and emit a JPEG at no more than 2.5 MiB so its JSON request remains below Vercel's 4.5 MB request limit.

The existing server continues independently decoding normalized bytes with Sharp, stripping source metadata, generating a server SHA-256, storing a private JPEG and verifying the exact stored object before signing. It intentionally does not depend on Sharp's optional system HEVC codec. Error copy describes a photo-preparation failure and preserves the staff draft; the shared UI assignment owns camera/gallery controls and in-flight save behavior.

Verify real 12/48-megapixel-compatible dimensions, representative HEIC decoding in an actual browser, portrait orientation, JPEG/PNG/WebP regression, spoofed/malformed/oversized files, and bounded JPEG output. Use local fixtures and mocked endpoint/storage dependencies only. Record observed browser coverage and any physical-iPhone limitation accurately. Run scoped TypeScript/lint/tests and have the coordinator run the complete production build before release.
