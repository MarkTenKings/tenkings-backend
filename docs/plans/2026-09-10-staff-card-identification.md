# Staff card identification — September 10, 2026

Mark requests rapid single-card entry from Front and Back photos using OCR plus specifically GPT-6 Astra. This is an optional read-only suggestion step for descriptive inventory fields; it does not change grading identity, create stock, infer cost/price/location, or write a catalog or financial record.

The authenticated staff endpoint accepts only the exact two private upload keys. Reuse managed storage HEAD/bounded streaming, then verify exact stream identity, length, JPEG shape and SHA-256 over the bytes submitted to the providers. Images never become public and no temporary signed URL is shared. Use the existing Google Vision key/endpoint with concurrent Front/Back document text detection, then the existing OpenAI key with `gpt-6-astra`, low reasoning effort, strict JSON schema and `store:false`. Public-image grader adapters cannot safely consume the private staff photos, so the bounded staff adapter is separate and changes no grader library or behavior.

Every suggestion is a nullable value, confidence and brief evidence. Missing, unreadable or conflicting fields stay unknown; a variant is suggested only if printed explicitly. Photo/OCR content is untrusted data. Reject unknown output fields, invalid structure, excessive lengths, URLs, HTML and credential-like output. Costs, prices, location and authority are absent from the request/output schema. Response provenance records the exact hashes, model and per-side OCR status without saving those facts as authoritative inventory identity. OCR failure is explicitly disclosed and can still permit photo-based Astra suggestions; Astra is never substituted.

Bound storage to six seconds, each OCR call to eight seconds, Astra to 25 seconds, and the whole operation to 40 seconds. Abort provider work on cancellation and close any open storage stream. Do not retry automatically. All errors preserve the entry and allow manual editing.

Validation covers human-session authorization before any reads, private responses, strict request keys, checksum/length/object mismatch, corrupt or oversized images, exact Astra settings, concurrent OCR, missing provider configuration, unsafe/malformed/refusal/incomplete model responses, slow headers/body, cancellation and sanitized failures. Use generated JPEG fixtures and injected provider/storage dependencies. A real provider smoke may use synthetic cards only; never inspect a private production photo or create inventory for proof. No commit, deployment, migration or credential mutation belongs to this assignment.

Official request references verified September 10: [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) supports images, structured outputs and low reasoning effort; [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) requires an object root, explicit required nullable fields and `additionalProperties:false`.
