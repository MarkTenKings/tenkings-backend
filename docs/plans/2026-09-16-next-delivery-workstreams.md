## Repository and hosting recommendation

Use the existing GitHub repository **https://github.com/MarkTenKings/tenkings-backend**, with the current application at `frontend/nextjs-app` and shared packages. A domain is an address, not a repository folder: collect is a subdomain of tenkings.co, but its Vercel application and the Wix root website currently have separate hosting. There is no Wix code/content migration to GitHub now that Mark has discarded the old content.

Recommend keeping the application on **Vercel**, initially as a host-aware public/staff shell in the existing app/project. It already runs the current Node/Next APIs and scheduled research work. Adding a new host requires explicit route/navigation boundaries; simply aliasing the old app is insufficient.

Cloudflare could optionally manage **DNS**, the records directing each hostname to its host. This is distinct from **Cloudflare Workers hosting**, which would require a separate runtime/framework compatibility effort. Neither a DNS-provider move nor a Workers migration is required to attach tenkings.co to Vercel. Avoid combining an unnecessary runtime migration with accuracy work and the first domain transition.

Vercel documents custom domains with external DNS and GitHub-backed projects: [domain setup](https://vercel.com/docs/domains/set-up-custom-domain), [GitHub integration](https://vercel.com/docs/git/vercel-for-github). Cloudflare documents its own Next.js deployment path: [Workers Next.js](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/). These capabilities were checked against official documentation; the recommendation is based on our existing application/deployment, not a claim that another host cannot support it.

Existing collect card/NFC/customer links and Atlas's separate application remain valid. The first clean shell can expose only implemented destinations, without fake future buttons or the old admin menu. Staff routing retains actual server-side human-admin authority; a new URL is not a new permission system.
