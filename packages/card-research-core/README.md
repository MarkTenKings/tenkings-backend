# Shared card research core

This package extracts Inventory's application `20643deae9b9b341fc7dfcd7fb703c53d0b73d0b` research engine through v6 into a host-independent ES module. `SOURCE_MANIFEST.json` pins every original TypeScript source. The source checkout was at documentation commit `4bcbd31c142c6326ddb32bfdbc2172fc28cccb10`. The shared catalog contract package is copied exactly from that source.

`researchCardSubject(input, dependencies, signal)` accepts a namespaced opaque subject, immutable revision hash, saved descriptive facts, and front/back photo descriptors. A descriptor binds transmitted bytes, MIME, byte count, original source hash, and an opaque host reference. The injected photo reader must return those exact bytes. The core never opens an Inventory storage key, imports a database or worker, reads ambient credentials, changes a catalog, or modifies a grade. Unknown byte count is permitted only for legacy compatibility input; retained result descriptors always record actual verified counts.

Dependencies own credentials/configuration, network effects, byte access, current catalog authority, and optional durable printing-scope acknowledgement. Default source count240 and Best Offer hydration preserve Inventory behavior. ATLAS deliberately supplies count40, no Best Offer hydration or sale-detail calls, and the approved report's existing identity-only query. The engine's version identifiers remain unchanged so evidence names the actual upstream policy.

The model records independent identity/variant/visual/condition booleans. Inventory's same-condition comparison and estimate policy remains intact: raw matches raw; a slab target matches only the same grader and numeric grade. ATLAS retains those decisions as annotations and projects supported external-grader sale facts through its existing market-review contract. It never adopts the Inventory estimated value, translates an ATLAS grade to another grader, or automatically publishes model selections.

`./inventory` is a compatibility wrapper for a host adopting this package. It restores the original unit/event/description/photo-key wire contract and injects Inventory's existing authorized photo reader. Optional recovery assessment requires the host's existing `applyRecoveryContext` validator. Inventory's source checkout and deployed application are unchanged; adopting this package there is a separate release.

The ported upstream suite exercises v1–v6 parsing, photographed identity, exact printing and season constraints, estimates, no invented Best Offer prices, deadlines, image ancestry/isolation, scoped published catalogs, and withdrawal of catalog authority. Inventory worker/recovery-ledger tests are outside this package; no worker, recovery mutation, ledger, ownership, or financial model is extracted. Neutral subject/photo tests cover the new boundary. Run with Node20: `node --test test/*.test.mjs`.
