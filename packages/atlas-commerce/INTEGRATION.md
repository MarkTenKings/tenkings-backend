# ATLAS commerce integration contract

This package is server-only except for the separate checkout component. No module imports Ten Kings payment, wallet, pack, tax, inventory or shipping writers. The optional Stripe adapter is an implementation choice, not evidence that an ATLAS merchant has been selected/qualified. All provider calls are injected and require ATLAS-specific configuration.

## Customer gateway

The existing authenticated `atlas_customer.customer_call` remains the customer SQL entry point. Its checkout/order outputs are explicit customer-safe DTOs; they never return raw provider snapshots. `GatewayCommerceRepository` receives an authenticated private `call(action,data)` closure created on the server, never a browser-supplied account ID. Internal worker/webhook calls require a distinct restricted commerce capability and MUST NOT mint a customer or REVIEWER session. The root integration supplies the following private repository actions; every mutation below is one transaction, with row locks and ownership checks:

| Action | Input | Output / atomic requirement |
| --- | --- | --- |
| `commerce_checkout` | `{draftId}` | `{draftId,revision,accountId,profile,profileRevision,phone,channel,cards,location,shippingPlans}`. Cards are exact owned verified pairs `{id,revision,photoPairHash,identity}`. Channel `MAIL_IN` or `KIOSK`. Location is server-resolved registry snapshot `{id,dealerId,revision,name,terminalId,terminalLocationId,schedule,address}`. Shipping plans are server-configured and measured, keyed by `packingPresetId` + service; client cannot supply addresses, weight or charges. |
| `commerce_save_quote` | `{expectedRevision,quote}` | Saved immutable quote. Recheck exact current draft/card/profile/location revision and roster hash. Never trust client-created quote objects. |
| `commerce_reserve_payment` | `{quoteId,requestId,attemptId,merchant,now}` | `{attempt,dispatch}`. Recheck quote expiry, current roster/profile/location, enabled merchant. Freeze draft; enforce one unresolved/paid attempt per draft and one active attempt per reader. Existing same request returns original; other request returns original attempt or conflict, never a second charge. Atomically persist `DISPATCHED` before returning dispatch=true. |
| `commerce_record_payment` | `{attemptId,observation}` | Attempt. Preserve immutable quote/request/merchant/provider ID; observation is server-provider evidence only. Unknown never releases reader/draft. Failed card presentation reuses PaymentIntent. |
| `commerce_payment` | `{attemptId}` | Owned attempt including original quote. |
| `commerce_confirm_paid` | `{attemptId,evidence,receiptId,effects}` | `{order}`. Revalidate exact paid provider ID, total, currency, merchant, metadata and quote hash. Unique provider ID/event and one order/draft. Commit order/paid lines/commission basis + separate EMAIL_RECEIPT/SMS_RECEIPT/TAX_TRANSACTION/FEDEX_LABEL effects together. Replays return same order. Release reader only after verified terminal result. Preserve profile, original schedules and original photos. |
| `commerce_order` | `{orderId}` | Customer-safe owned order/receipt/effect states; never payment secret or carrier credentials. |
| `commerce_claim_effect` | `{effectId,claimId}` | `{effect,dispatch}`. Restricted worker only. Claim PENDING exactly once. A stale DISPATCHED claim becomes UNKNOWN, not redispatchable. |
| `commerce_finish_effect` | `{effectId,claimId,state,result}` | Restricted worker only; reject different claim or overwriting terminal evidence. Store original provider receipts/label bytes privately. |
| `commerce_pending_effects` | `{}` | Restricted worker discovery of up to 20 PENDING IDs. Expired DISPATCHED claims become UNKNOWN. The service checks adapter availability before claiming, so missing configuration leaves an effect pending. |
| `commerce_reconcilable_effects` | `{}` | Restricted worker discovery of up to five UNKNOWN FedEx effects with real async job IDs. Persisted maximum five read-only retrieval attempts, with 1/2/4/8/16-minute backoff. Never create another shipment. |
| `commerce_label` | `{orderId,effectId}` | Customer-owned successful label PDF, MIME, base64 and raw-byte SHA256; private object is never fetched through an arbitrary external URL. Maximum raw PDF 4 MiB. Package-label `GENERATED` does not establish physical printing. |

Provider webhook ingestion verifies exact raw body/signature and merchant/mode, then uses provider retrieval and the same confirm-paid transaction. Event IDs are deduplicated in `CommerceProviderEvent`. Browser redirect, terminal command ACK, print command and scheduled pickup are never paid/custody evidence.

## HTTP + UI

Recommended routes under `/api/customer/commerce`: GET `checkout?draftId`; POST `quotes` `{draftId,expectedRevision,packingPresetId?,shippingServiceCode?}`; POST `payments` `{quoteId,requestId}`; POST `payments/:id/reconcile` `{}`; GET `orders/:id`. Existing session, same-origin and CSRF checks apply. Use a separate raw-body `/api/commerce/provider-webhook` endpoint with no customer-session shortcut. Never expose generic gateway actions.

`CommerceCheckout({draft,request,onPaid,onBack})` uses `request(path,{method,body})` returning parsed JSON. `draft` has `id` or `draftId`, `revision`, `channel`, `cards`. The supplied request wrapper owns `/account` prefix, cookie and CSRF handling. A provider result may contain `clientSecret` and `publishableKey` for the current customer's active attempt only. Stripe Elements collects PAN; ATLAS receives no card data. `onPaid(order)` runs only on a server-confirmed order.

Saved checkout source includes `activePayment.order` after confirmation. The saved paid receipt is recovered before current live kiosk/provider validation, including when a kiosk has since been disabled. The label route is GET `orders/:orderId/labels/:effectId`; only that read has a 6 MiB JSON response allowance for the bounded 4 MiB PDF. Other customer reads retain their 512 KiB cap. Browser verifies PDF bytes/hash before download.

Customer response contracts use independent allowlists in `src/projections.mjs` and SQL `commerce_public_*`. Quote/order receipts retain customer totals, card identity and unit prices, turnaround terms, location/address/schedule and shipping-leg amounts. They omit account/profile/phone, photo/content/request hashes, commissions, merchant/dealer/device IDs, raw tax/payment/provider evidence and carrier shipment requests. Nested card identities, schedules and effects are allowlisted too; newly added internal fields remain private by default. Stored quotes/receipts remain unchanged for private payment, shipping and dealer processing. `commerce_call('commerce_checkout')` returns a tagged `atlas-commerce-checkout-v1` safe DTO, also accepted by disabled-provider checkout reads; authenticated private `commerce_provider_call('commerce_checkout')` still returns the complete internal source. Only the current MAIL_IN AWAITING_PAYMENT result may carry its provider-issued client secret and publishable key for the secure payment form.

`createCommerceProviders(env,{fetchImpl})` returns `{enabled,payment,tax,carrier,notifications,packageLabel,binding,terms}`. `CommerceService` accepts these adapters and an authenticated `GatewayCommerceRepository(call)`; provider effect workers use the separate private service authority. Root owns `atlas_customer.customer_private_call` and signed private HTTP wiring. The package SQL proposal is a reviewed source for root migration integration, not a deployment command.

## Required configuration

Mail turnaround event and charged legs are deliberately `UNCONFIGURED` until owner decisions. Missing tax configuration blocks all payable quotes; a real provider calculation of zero is accepted with its source. Kiosk shipping is always exactly zero. Measured package presets and actual origin/destination/service/tender date are required for FedEx. Unknown shipment creation cannot be retried automatically; recover actual async job or provider evidence and saved label first. Notification delivery unknowns do not replay without provider reconciliation. Tests cause no live provider effects.

Measured mail plans use `atlas-measured-shipping-plan-v1`: exact `cardCount`, sourced `measurementReference`, preset/service identity, explicit UTC `validFrom`/`validUntil` quote-admission timestamps at most24 hours apart, and required per-direction shipment templates with origin `shipDateTimeZone`. Each template binds positive measured weight/dimensions and an actual calendar ship date which has not passed locally. Only the ATLAS party is required in configuration; the customer party comes from the confirmed profile. Checkout options are filtered by count and current validity; the browser request remains unchanged. The private quote adds the exact `shippingPlan`, which is deliberately absent from customer DTOs. SQL matches the configured plan and complete customer-substituted request, not merely a self-reported request hash. Quote expiry is capped by plan validity.

A delayed pending label whose saved ship date has passed stays pending with `SHIPPING_DATE_EXPIRED` before claim/provider dispatch. Resolution requires actual operational evidence; no request/date is silently replaced. Existing UNKNOWN label reconciliation remains read-only against its original provider job. See CONFIGURATION.md for the complete cold plan contract. Source tests and the fixture's invented measurements/dates do not qualify real packaging, carrier service or customer shipping.
