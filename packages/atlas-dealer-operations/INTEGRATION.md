# Dealer operations integration

Additive SQL follows customer intake and commerce. The initial registry and membership roster are empty. No supplied contact-only shop becomes an enabled kiosk. Root owns migration publication, gateway integration and production controls. No provider, device, physical custody or transfer effect is performed by installation.

The sole customer database function remains `atlas_customer.customer_call(text,jsonb,jsonb)`. After its usual exact control binding validation, delegate to `atlas_dealer.customer_call(action, accountId, controlRevision, data)`:

- `dealer_locations`: allow before sign-in, pass null account. Returns public locations and exact QR/NFC token resolution, never terminal IDs or customer records. `data.entry` is attribution only.
- `dealer_memberships`: authenticated customer receives only their active assigned location IDs/names for portal selection.
- `dealer_enter`: require the ordinary current verified customer session first. An explicitly provisioned location membership is also required. Input `{locationId,dealerSessionHash,browserHash}` produces an independent eight-hour dealer session bound to browser, membership version, account access version and control revision. The JS service mints a fresh opaque token; store it in the separate HttpOnly dealer cookie.
- `dealer_read` / `dealer_logout`: do not require a customer session as dealer authority; SQL checks the independent dealer session and membership. Logout also needs ordinary same-origin + dealer-specific CSRF before dispatch. No customer or dealer request supplies an authoritative account/location to projections.
- `dealer_orders`: authenticated customer keyset-paginated paid order history, twenty records per page and an opaque owned order UUID cursor.
- `dealer_tracking`: authenticated customer `{orderId}` → their paid card tracking only. Keep legacy CustomerSubmission/StaffSpecimen tracking beside it, unchanged.
- `dealer_deposit`: authenticated customer `{orderId,cardId,requestId}` → immutable declaration only. A declaration does not confirm physical collection or presence.

`atlas_dealer.staff_call(action,sessionHash,browserHash,staffBinding,allowedPhoneHashes,data)` authenticates a current genuine REVIEWER via `atlas_manual.authenticate`. Actions are `read`, `location_configure`, `membership_configure`, `custody_record`, `bind_manual`. `read` returns at most 1,000 configured locations, 100 latest paid orders with scoped card tracking, current memberships and 100 accessible unlinked manual card IDs. Configuration and membership mutations additionally require the existing exact deployment-bound `StaffOperationsGrant` plus a genuine staff session no older than five minutes; there is no invented grant or automatic activation. It is a narrow private staff function; no customer/dealer grants. Configuration actions require server-authorized staff operation routing; dealer members cannot operate them. Physical event inputs require actual time and evidence reference. Bind a current `atlas_manual.card` only after recorded ATLAS receipt and current staff edit authority. There is no grading on pre-arrival uploads and no automatic physical event from schedules.

`location_configure` takes `{id,dealerId,expectedRevision?,enabled,name,address,position,schedule,terminalId,terminalLocationId,packagePrinterId,entryToken,authorizedUntil}`. Address uses `{line1,city,region,postalCode,country}`; actual coordinates are required. QR/NFC uses `/account/submit?kiosk=<entryToken>` and server entry resolution; direct selection is revalidated. Schedule is `{timeZone,pickups:[{weekday,time,cutoff}],returns:[{weekday,time}],exceptions:[{date,kind,cancelled,time?,cutoff?,reason}]}`. Sunday=0; time/cutoff are 24-hour HH:mm in the IANA timezone. Exceptions override a kind on a local date. Nonexistent DST slots are skipped, repeated hours use PostgreSQL's standard-time choice. Cutoff is strict: at the cutoff choose the next slot. Date projections search 64 days and remain unavailable if no route exists. The service target is seven local days from actual collection; schedules never assert it happened.

`atlas_customer.intake_location(uuid)` supplies current enabled snapshot with private terminal/printer IDs plus `schedule.nextCollectionAt/projectedReturnAt/cutoffAt`. Only public directory projections reach anonymous pages; checkout/receipt should strip private device identifiers before browser delivery. Original paid schedule/location is preserved. Current route changes and explicit delay notes appear separately in tracking.

The `CommerceOrder` AFTER INSERT trigger requires the payment already set PAID in the same transaction. It materializes each exact paid line and accrues exactly 500 cents only for a KIOSK line with unitCents=5000 and commissionCents=500. Taxes/shipping are never commission bases. All order/card/commission evidence is immutable and ledger totals derive from rows. `reverse_commission(cardId,refund)` is restricted internal commerce evidence entry with exact original provider payment, successful refund event/hash, actual refunded grading amount and an explicit policy reference/commission reversal amount. It does not select a refund policy or issue money. Never grant it to customer/dealer roles.

Public page uses `@atlas/service-bridge/customer-service` client with only `ATLAS_CUSTOMER_DIRECTORY_KEY` and `ATLAS_CUSTOMER_SERVICE_URL`; the dedicated server key may call only the public reads `dealer-locations` and `weekly-capacity`. GET `/account/api/customer/intake/locations` uses the same projection and optional query/coordinates; GET `/api/capacity` returns the bounded card-capacity projection and reports NULL quotas as `NOT_CONFIGURED`. Neither read grants customer/session/payment authority. No geocoder, location permission or external map loads without customer action. Google keyless location iframe uses `https://maps.google.com/maps?q=<actual coordinates>&z=14&output=embed`; allow that exact origin in frame-src. Public Google API maps remain available when configured.

The `/account/dealer` page and `/api/customer/dealer/{session,memberships,logout}` routes use the separate dealer cookie and route CSRF. `DealerPortal` renders the SQL projection; `DealerWorkspace` handles existing phone-login proof, approved-location selection and dealer-session exchange. It shows counts, order references, physical progress and accrued/reversed commissions. No names, phones, addresses, private notes/grades, tax/payment details or other locations are returned.

Customer HTTP routes are `GET /api/customer/orders?cursor=`, `GET /api/customer/orders/:id`, and `POST /api/customer/orders/:id/deposit` with `{cardId,requestId}`. The server owns the route order binding and customer identity. `CustomerOrderHistory` mounts alongside preserved legacy submission history; `/account/orders/:id` and paid-checkout confirmation mount `CustomerOrderTracking`. Customer deposits persist their operation ID locally across uncertain replies; no declaration advances physical custody. Current `atlas_manual` approval produces a link only after its exact publication is PUBLISHED.
