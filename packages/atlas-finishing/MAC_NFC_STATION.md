# Mac NFC station core — source-only checkpoint

**This is not a deployable Mac NFC station and is not hardware acceptance.** The station algorithm, ACS Type2 data commands and durable recovery are implemented. The production PC/SC session binding, protected enrollment/signer, signed hosted authorization/acknowledgement endpoints and qualified F8215 identity/lock implementation remain missing. No new native writer executable or arbitrary-URL/APDU endpoint is installed or exposed. The existing diagnostic executable keeps its fixed URL and restrictions.

`@atlas/finishing/mac-nfc` exports `createMacNfcStation`, `encodeApprovedNdef`, and `createQualifiedType2Io`. Importing or constructing these performs no device discovery, connection, write or lock. The data primitive commands mirror the existing native `CAtlasNFCDiagnostic/diagnostic.c` read16 and four-byte user-page write operations; security-page addresses and lock masks are deliberately absent. A separate native binding can call existing PC/SC APIs, but the diagnostic's private static functions are not a dynamic production API.

## Required protected dependencies

- `profile`: exact `atlas-mac-f8215-production-v1` ID, external qualification evidence hash, reviewed safe user-page interval, and reviewed `identifyWritable(session)`, `lock(session)`, `verifyLock(session)` implementations. A successful CC/header sample alone cannot qualify these. The profile is trusted station configuration, never browser/model input.
- `signer`: enrolled station/enrollment/key identities, protected-key capability, `sign(bytes)` and local verification. The test signer is explicitly synthetic. Mac Keychain/Secure Enclave enrollment and protected key ownership are not supplied here.
- `authority.verifyArm`: verifies a signed hosted authorization for exact intent/plan/profile/station/enrollment, stable nonce and the explicitly associated card's bounded expiry. Calls must return that exact verified claim. The application cannot substitute a boolean. The bridge must durably retain the original signed authorization; renewal/reconciliation policy is separate.
- `pcsc.connectExclusive`: a bounded, exclusive native session with `read16`, `writePage`, transient same-tag checking, native observed removal, and reliable close. `pcsc.observeEmpty` is a bounded native reader observation for restart recovery. Raw UID/ATR/header stays inside the native session and is never persisted or included in hosted receipts. Node-to-PC/SC binding, native event loop, presence/removal observation and watchdog integration are not supplied here.
- `host.acknowledge` and `verifyAcknowledgement`: an idempotent authenticated result endpoint and cryptographic verification of its committed acknowledgement, bound to exact receipt hash/intent/station/enrollment. No current Windows receipt profile is impersonated. These new hosted protocol endpoints and their enrollment migration remain implementation work.
- `journal`: one authoritative protected directory per enrolled station, consistently used by every process. `createFileMacNfcJournal` implements the durable station-wide slot and history, requiring native `fullSync(fd)` (Mac `F_FULLFSYNC`) with no weaker default. Protected directory provisioning and the native full-sync binding remain bridge work.

## Executable lifecycle

1. `prepare({plan,association})` verifies exact immutable production plan and signed arm claim, then durably reserves the station-wide intent. It returns `WAITING_FOR_TAG` without touching a reader. An unresolved different intent is refused even after process restart.
2. `onTagPresent({plan,association})` atomically claims that saved intent before acquiring the exclusive native session. It verifies the qualified writable tag and an empty affected NDEF region. Tag identity is rechecked before every data mutation/read.
3. The core encodes the exact versioned approved report URL. It writes each four-byte user page once, publishes the NDEF header last, verifies each page and the full payload/padding, and checks that trailing bytes are unchanged. A durable write-intent precedes every possible data write; the entire operation is never automatically repeated.
4. Readback becomes a separately saved fact. The qualified profile alone supplies locking. Native lock verification plus another exact payload/trailing-byte readback must succeed before `lockVerified` becomes true. Unknown lock results retain the earlier readback fact without claiming a lock.
5. The enrolled signer signs a fixed allowlisted result containing hashes and station/job identity, with no UID or UID digest. Its durable result survives a lost hosted response. Only a cryptographically verified committed host acknowledgement changes `hostedAcknowledged`.
6. Native observed removal is separate. The station releases its slot only when readback, lock, host acknowledgement and removal all exist (`NFC_COMPLETE`). This is NFC station completion; assembly and welding remain `NOT_RECORDED`.

`recover` never writes user or security pages. Interrupted processing/write/lock phases become `UNKNOWN` and retain the station slot. A fully verified lock can finish signing; a saved signature can retry the exact host acknowledgement and native empty-reader observation. Expired authorization remains unresolved; it is not silently extended. `status` can still expose the saved facts. There is no operator override or automatic unknown-result clearing endpoint in this core.

The file journal serializes different processes with a private atomic directory lock, uses compare-and-swap revisions, keeps every completed intent to prevent re-encoding, and retains a crashed mutex for explicit reconciliation. It never times out/deletes that lock at startup. Its history is bounded to 4096 intents/16 MiB; reaching that limit stops admission until a reviewed archival mechanism is added, not by discarding replay protection.

## Verification and deployment gap

Eight injected-effect tests exercise cold arm, dynamic exact NDEF bytes, header-last ordering, readback and lock distinctions, wrong/uncertain host acknowledgements, native removal gating, restart recovery, expired authorization, unsupported/swapped/nonempty tags, concurrent callbacks, station-wide exclusion across recreated journals, completed-intent replay and crashed journal locks. They do not run PC/SC, install drivers, write/lock a tag or contact a host/provider.

To ship: implement the protected native session/executable and full-sync binding; qualify the actual F8215 profile and permanent lock coverage using documentation plus controlled hardware overwrite rejection; implement protected Mac key enrollment and the additive signed hosted protocol; pair the browser/station safely; then verify physical card association, phone reading, interruption recovery, printer/NFC coexistence and measured throughput on actual hardware. The existing fixed-URI diagnostic does not fulfill those missing executable/protocol paths.
