# ATLAS research and catalog integration

The staff research action uses the current approved report identity and the original photo lineage already bound to that approval. `research-photos.mjs` reads verified decoded frames and creates bounded JPEG research derivatives; neither grading originals nor approved report artifacts are changed. The v6 shared core performs sold-listing/photo/variation research. Results return the existing market-compatible preview plus private research annotations. Deliberate selection uses the unchanged market-selection endpoint and appends optional report presentation.

The `research_effect` journal belongs to the existing `presentation_market` intent. The original single STARTED/READY/UNKNOWN reservation cannot represent several independently dispatched sources/images/model/catalog calls, raw replies, usage, or late acknowledgements. Existing immutable artifact storage retains the bytes but cannot itself authorize an ordered dispatch or bind a late response to the admitted actor/report/request. This narrowly scoped journal supplies that missing authority; it introduces no catalog schema or inventory authority.

Research reservation and INIT share one transaction using the server-owned `reserveMarket` callback. The journal binds current reviewer/card/actor/report scope and a policy hash. Each exact effect envelope is stored before a contiguous DISPATCH. Its exact response bytes/hash and numeric usage are stored before response acknowledgement and result adoption. Receipts are append-only. A restricted SQL function may acknowledge only an already admitted exact DISPATCH after caller disconnect, session expiry, or superseded approval. It cannot dispatch work. Re-entry reads acknowledged effects; an unknown SOURCE/MODEL/image outcome never buys that effect again. A running request can outlive the caller's HTTP response; the same request observes PENDING and later its saved result. Process death after dispatch remains honestly unknown unless actual response evidence was retained.

Catalog access uses only the existing fixed `collect.tenkings.co` discover/lookup/media/proposals facade and a scoped service token. Full publication pins, coverage, exact media bytes and independent image ancestry are checked. Separate currentness checks have distinct durable purposes; replay does not collapse an end-of-run revocation check into an earlier response. A saved result's catalog authority is revalidated before displaying it. Missing publications remain unresolved; no machine output becomes published catalog authority.

An explicit contribution shares a metadata-only unreviewed observation: approved descriptive identity, pseudonymous physical-record reference, source hashes, and a derived research hash plus advisory proposed variant/positive treatment. It shares no image bytes, private object keys, staff identity, unit ownership, money, grade, or image rights. The host alone owns authorized Set Ops review/publication. The accepted receipt includes exact proposal/idempotency hashes. If the first response is lost, a subsequent explicit contribution action may reconcile only that identical host-idempotent proposal. There is no automatic retry loop, new observation id, or SOURCE/MODEL exception. A concurrent recorded/replay reply preserves the first durable receipt. An acknowledged unavailable host reply stays immutable; an explicit retry admits one new receipt attempt with a distinct private purpose and the identical host proposal payload.

Configuration requires enabled presentation/market, `ATLAS_MANUAL_RESEARCH_ENABLED`, existing `ATLAS_MANUAL_OPENAI_KEY` and `ATLAS_MANUAL_SOLD_COMPS_API_KEY`. Catalog is separately controlled by `ATLAS_MANUAL_CATALOG_ENABLED` and `ATLAS_MANUAL_CATALOG_TOKEN`. Construction makes no network calls. External host activation needs its existing catalog flags, configured token digest/scopes, and actual authorized reviewed publications; those are deployment/owner tasks, not fabricated by fixtures.

`sql/research-effects-proposal.sql` is identical to tracked staff migration `20260924030000_manual_research_effects`. `researchGrantSQL` grants only SELECT/INSERT on this journal and execution of its restricted receipt function. It adds no cross-application database grants. `scripts/validate-research-postgres.mjs` runs the tracked migration chain and authenticated workflow in owned disposable PostgreSQL with synthetic provider responses; `ATLAS_RESEARCH_EVIDENCE` must name a new absolute owned output directory. No real provider calls, human approvals, catalog publications, hardware actions, or live completion are claimed by those fixtures.
