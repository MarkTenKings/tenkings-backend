# Canonical ATLAS grading core

This is the existing Speedster/ATLAS grading implementation shared by both applications. `extraction-manifest.json` records ten byte-preserved source modules and their hashes, anchored to Ten Kings source da2a34da. The build also includes the report and review-action contract entries. Historical frontend import paths forward to those same sources. Existing rule/version, 70/30 Front/Back weighting, equal subgrades, thresholds, contour coordinates, trace handling and identity behavior are unchanged.

The package exposes only named grading, identity, geometry, finding, trace and report entries. It has no ambient HTTP, provider, database, credential, storage or human-approval dependency. Existing async scan/re-measure helpers can invoke explicitly supplied callbacks; the caller still owns authorization, admission, reservations, source validation and provider transport. The full existing review service is required for actual detection/corrections and calibrated Memory admission.

`report` is a new deterministic content adapter. It derives centering from confirmed quads, parses persisted findings, recomputes using the canonical formulas, and rejects a saved grade that differs from recalculation. Draft content preserves unreviewed findings. Final-content calculation applies existing completion semantics but neither issues approval nor publishes, certifies, changes learning or writes a card. The calling human-approval transaction must enforce that authority. The presentation projection uses the existing public finding-state whitelist and excludes Memory exemplars, internal annotations, fingerprints and trace/mask bodies.

Build with `pnpm --filter @atlas/grading-core build`; test with `pnpm --filter @atlas/grading-core test`. The build checks the actual esbuild dependency graph against the closed module list and existing zod dependency. Generated ESM files are ignored and rebuilt from canonical sources. Legacy TypeScript compatibility modules use canonical source directly. The staff app builds the package before dev/test/build.

Validation at extraction: 191 existing grading/geometry/review/session/map/trace tests, five report/source-integrity tests, strict TypeScript check of the report and its dependency closure, and the full legacy app build with Sharp runtime trace validation. These are software checks, not optical accuracy or current-worker acceptance. The report is not yet connected to staff persistence or publication at this extraction milestone.
