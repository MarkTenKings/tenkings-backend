# Native Mac companion — September 22 source checkpoint

The companion builds and its protocol runs. **Production NFC is not activated or hardware-qualified.** The compiled F8215 qualification registry is intentionally empty: `qualifiedProfileAvailable:false`, `productionReady:false`, signed arm state `VERIFIED_UNQUALIFIED`, and `open`/data writes refuse `COMPANION_PROFILE_UNQUALIFIED`. Runtime JSON cannot enable a lock algorithm. No F8215 lock addresses or masks are guessed.

This separate executable leaves the read-only probe and fixed diagnostic writer unchanged. `AtlasMacNFCCompanionCore` validates authority and owns signing policy; `CAtlasNFCCompanion` owns exclusive PC/SC connection, transient tag continuity, data bounds, exact header-last NDEF writes, page/full readback, native removal, cleanup and watchdog. Raw UID/header/ATR never leaves native memory. A lost write reply poisons the session and cannot repeat a page. The Node station journal reserves the intent before any native open/write and prevents process-restart rewrite.

## Commands

Build with `swift build --package-path packages/atlas-mac-nfc --product atlas-mac-nfc-companion`. The executable is `.build/debug/atlas-mac-nfc-companion` under that package. Commands are explicit; importing the Node packages or calling capabilities does not inspect a reader or Keychain.

- `capabilities`: one JSON object, cold. Fields are `protocol:atlas-mac-companion-rpc-v1`, `qualifiedProfileAvailable:false`, `productionReady:false`, `protectedSignerAvailable:true`, `keyCreationAvailable:true`, `fullSyncAvailable:true`, `profile:atlas-mac-f8215-production-v1`. Availability means implementation exists, not that a key is enrolled or hardware qualified.
- `serve --configuration /absolute/private/config.json`: bounded newline JSON IPC over stdin/stdout, never an HTTP listener. Requests are at most32768 bytes and sequential. Responses are `{id,ok:true,result}` or `{id,ok:false,error:CODE}`. Unknown/extra fields are refused. A native watchdog bounds operations to6.5 seconds and idle input to30 seconds; cancellation terminates the child, without a retry. Core dumps are disabled.
- `full-sync --fd 3`: inherited descriptor only, owned private regular file, `fsync` plus `F_FULLFSYNC`, returns `{synced:true}`. It takes no path. Failure is fatal to durability; there is no weaker success fallback.
- `key-info --configuration ...`: queries only the configured existing Secure Enclave P256 private key, verifies actual token/type/size, and returns public SPKI/fingerprint and configured enrollment identity. It neither creates a key nor exports private material. Authentication UI is disabled.
- `init-key --configuration ...`: **explicit operator setup mutation, never automatically called**. Creates one permanent Secure Enclave P256 key with device-only, unlocked access and private-key-use access control. A durable exclusive initialization marker prevents concurrent/repeated attempts; existing keys are refused. No delete, replace, export, recovery reset or software-key fallback exists. An interrupted marker requires operator inspection. Tests never invoke valid key creation; this path needs signed-app/device acceptance.

The protected configuration must be a regular nonsymlink file owned by the station OS account, mode0600 or stricter, in an owned private0700 directory. Its exact fields are `version:atlas-mac-companion-config-v1`, `stationId`, UUIDv4 `enrollmentId`, `keyId`, `hostKeyId`, base64DER P256 `hostPublicKeySpki`, `protectionEvidenceHash`, and `profile:{id,profileHash,qualificationHash,firstUserPage,lastUserPage}`. Profile ID is `atlas-mac-f8215-production-v1`; profileHash is SHA256 of canonical sorted JSON of its other four fields. The Keychain tag is derived from enrollmentId/keyId, never arbitrary input. Protected configuration does not establish remote attestation: hosted activation separately pins the actual public-key fingerprint and a reviewed protection/qualification receipt.

## IPC authority and recovery

`arm {envelope}` verifies ES256-DER against the pinned host key **before parsing claims**. Claims use the shared `atlas-mac-nfc-arm-v1` wire contract: exact station/enrollment/key/profile and approval bindings, versioned `https://atlasgrading.com/reports/ar_...?v=...` URL, exact NDEF hash, nonce, issuedAt and expiry at most15 minutes. The native encoder independently reproduces and hashes the NDEF. A different active authorization is refused. Host-approved arm data never enables a missing native qualification implementation.

Allowed operations are `presence`, `open`, `read16 {page}`, `write4 {page,hex}`, `same-tag`, `wait-removed {timeoutMs}`, `observe-empty`, `identify-qualified`, `lock-qualified`, `verify-lock`, and `close`. There is no `transmit` or generic command. `presence` returns `EMPTY,selected:null` or `PRESENT,selected:0|1`; selected is the resolved Mac alias index, not a count. It rejects ambiguous, unsupported or busy interfaces. `read16`/`write4` are bounded to the signed qualified user interval; writes must match the next exact approved NDEF page and bytes. Lock operations always return unavailable in this source checkpoint.

`enrollment-proof {envelope}` verifies the signed two-minute hosted challenge and signs only the fixed proof containing the actual station public key, enrollmentId, challenge hash and configured evidence hash. The response includes `{enrollmentId,keyId,publicKeySpki,protectionEvidenceHash,signature}`. Possession alone cannot activate a station.

`sign-receipt {receipt}` requires native readback and qualified permanent-lock verification, and accepts only the exact fixed WRITE receipt derived from the active arm. `accept-ack {envelope}` requires an exact signed hosted WRITE acknowledgement for that signed receipt. `sign-removal {receipt}` additionally requires a native observed removal/empty state and the verified hosted acknowledgement. It cannot sign arbitrary JSON.

`restore-receipt {envelope,receipt,signature}` is the restart path: verifies the current unexpired host arm, exact fixed WRITE receipt, and prior signature against the actual protected station public key. It permanently places that child in read-only recovery: no open, read16, write, lock or new WRITE signature. Only native presence/empty observation, exact host acknowledgement and fixed removal signing remain possible. A saved signature cannot authorize a new tag write.

Expiry forbids new RF observation or new signatures. Exact saved signed receipts/acknowledgements may be relayed after expiry; the host returns a late WRITE acknowledgement only for an already committed result. Already-signed removal may also be relayed. No new removal signature is minted after expiry, and an unfinished expired removal remains unresolved. Cleanup/LEAVE_CARD remains permitted. The browser/Node bridge must retain durable receipt custody and start a fresh native child only after committed hosted removal completion.

## Tests and remaining acceptance

Run `python3 packages/atlas-mac-nfc/scripts/test-companion.py` (Node20 defaults to `/opt/homebrew/opt/node@20/bin/node`, override `ATLAS_TEST_NODE`). It compiles fake-PC/SC fault fixtures without linking real PC/SC, tests a temporary-file native full-sync and synthetic watchdog, runs Swift protocol tests with CPU-only fixture keys, and exercises actual Node→native signed arm rejection plus Node→Swift fixture recovery/signature interoperability. The fixture executable is separate from the shipping companion; the shipping executable has no environment-selected key or hardware provider. No reader/Keychain/driver/provider calls occur in these tests. Current suite:21 C-PCSC,4 platform,30 Swift protocol and17 cross-language checks.

Remaining acceptance: authoritative F8215 identity/memory/permanent-lock evidence and a reviewed compiled lock implementation; controlled hardware read/write/overwrite-rejection/removal/phone/restart tests; operator station key creation and host allowlist activation; signed/notarized packaging, OS permission and protected key access acceptance on the actual Mac; printer/media physical qualification and measured end-to-end throughput. Local source tests establish executable behavior, not these physical or release properties.

Key API reference: [Apple Secure Enclave key guidance](https://developer.apple.com/documentation/security/protecting-keys-with-the-secure-enclave). The existing ACS PC/SC references and observed diagnostic limitations remain in [README](README.md).
