# ATLAS R2 marketplace pilot

Default-off, isolated implementation of an ATLAS-held fixed-price marketplace. Importing or constructing this package does not register routes, apply shared migrations, read grading credentials, start jobs or change grading/Ten Kings. Hosted recovery requires separate approval and an explicit start. Ownership claims and customer ownership history remain disabled pending Fingerprint and separate authority/policy approval.

## Local preview and tests

Use Node 22.16.0 or later with `node:sqlite`, from the repository root:

```sh
node --test packages/atlas-marketplace/test/*.test.mjs
mkdir -m 700 /absolute/owned/new-demo-directory
node packages/atlas-marketplace/scripts/demo-server.mjs --synthetic-local --data-dir /absolute/owned/new-demo-directory
```

The server prints its random loopback URL. `/` is the explicit synthetic seller/buyer/staff workspace; `/marketplace/` is the public catalog. The directory must exist, be absolute and resolve without symlink parents. Reopening it retains original intents and provider state. Use a new directory for a fresh demonstration; never erase uncertain financial state to retry. Stop with Ctrl-C. The public sign-in link targets the intended `/account/marketplace/` integration mount, which the standalone demo does not implement.

The demo uses synthetic identities, artwork, policy and provider effects. The illustrative $5 fee, $12 shipping, $10 tax and zero return window are fixtures. No actual customer, inventory, shipment or money is involved. The owner-approved pilot is 8% of card price including ordinary processing, no listing fee/buyer premium/standard withdrawal percentage, and 24 hours after evidenced delivery followed by staff-reviewed release. Use the explicit pilot-policy builder for those terms; the legacy demo does not select production configuration.

| `ui/` | Public filters, exact card evidence, seller listing lifecycle, buyer quote/reservation/payment, staff fulfillment/refund queue, USD proceeds and bank-payout status. Synthetic controls exist only in the local demo mode. |

`ui/workspace.html` loads relative assets. Configure customer routes inside the existing `/account` cookie path and staff routes inside the existing staff cookie path; pass matching `mountPath` and `apiPath`. `auth-r1.mjs` takes canonical R1 class instances and explicit audience/role policy. REVIEWER alone can map to STAFF; OBSERVER is refused. The customer passive-session gateway in `sql/r1-session-access-proposal.sql` is intentionally guarded and unapplied. Shared signed-ingress allowlists and route registration remain R1 integration work.

The Stripe UI can confirm only its original buyer/reservation capability. Client secrets stay ephemeral and are removed from return URLs before application reads. A 20-second Element-readiness deadline disposes a stalled form and directs recovery of the original payment; it never submits payment. Link is disabled with `wallets: { link: 'never' }`, and provider evidence must satisfy the supported card-funding contract. Raw webhook verification uses the exact received bytes; payment and early-dispute events settle the original order without requiring a buyer return. A financial review hold is preserved while settlement completes.

Stripe payout eligibility is not proof of bank ownership. Actual account capability, manual payout schedule, supported bank destination and fresh platform/connected reconciliation are independently required. A provider outage leaves saved work visible and removes payout readiness. ATLAS Balance represents USD sale proceeds; it has no connection to Ten Kings TKD. Spending proceeds, dealer/direct shipping and offers remain outside this pilot. Optional instant payout is implemented but disabled pending actual eligibility, pricing, bank ownership and provider-fee qualification; standard payout evidence does not qualify instant payout.
