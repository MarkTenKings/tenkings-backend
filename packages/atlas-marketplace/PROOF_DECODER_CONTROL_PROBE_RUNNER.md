# Root-only finite control probe runner

This source runs one explicitly selected native control probe on the dedicated R2 host. It remains default-off and `PROBE_ONLY`; it grants no decoder validation, customer publication, ownership or runtime admission. The production worker command, original-image request schema, transport and result parser remain unchanged.

The only image accepted is `127.0.0.1:5001/atlas-r2-control-probe@sha256:961dacfae60d2a302f4699ab7c26c587833aac54dfcf25c1a7b8060140dfe999`. Its C ELF SHA is `fc2319114c03ea7b57356236ea4c56ba86c28ec67f333dcc69c283dacbe1dbdc`; its inventory SHA is `79684669028ba1f8e6eff594d4ae1fadc15201fd81c463ad6fe978a29b08ed15`. It substitutes that ELF at the fixed executable path in a distinct image. Inherited profile `nodeVersion` describes the comparison baseline, not the actual executed probe ELF. This image must never be used as decoder qualification evidence.

The comparison controls are pinned: amd64, UID/GID65532, one worker, 15 seconds, 512MiB memory with no swap, CPU150000/100000, pids32, nofile64, tmpfs/shm8MiB. Seccomp path `/etc/atlas-r2-decoder/security-01/seccomp.json` and SHA `5f179abeafd17a18dbb6d0617fbda4a980d9b941e984b270f438ffdaebf47ede`, and the reviewed named AppArmor policy are fixed in the pure probe-plan validator. Failures do not widen the policy.

## Concrete boundaries

`registry.reserveControlProbe({requestId, mode, nonce, deadlineBootNs})` is a separate root-only entry point. It derives the exact 48-byte challenge using the existing nine-mode encoder. It persists a closed tagged request plan containing schema, `PROBE_ONLY`, mode, nonce, byteCount48 and SHA256. Existing `reserve()` remains image-only; the tagged challenge cannot pass `assertProofDecoderPlan`. Persisted ordinary image records keep their original shape.

`createProofDecoderTargetControlProbeSession` requires real controller, observer, guard lease, fixed-parent binding and same-process target registry. Its only execution method is `run()`. It owns IMAGE_INSPECT, durable CREATE, pre-start INSPECT, ATTACH, durable START, running INSPECT, native input barrier, exactly 48 input bytes with FIN, bounded probe output and WAIT. It accepts no command, image, syscall list, callback, HTTP parameter, fixture connector, original byte buffer or parser option. Each CREATE/START intent is durable before the concrete socket effect; no retransmission is allowed.

The separate concrete probe transport uses fixed `/run/docker.sock`, API1.47, protected root socket/ancestor inode checks and atomic native peer lifetime observations. PID1 may be the systemd socket peer; this does not authenticate a dockerd PID. The transport has a private finite sequence, at most seven request operations and two sockets. HTTP bodies are at most262144 bytes, headers8192 bytes, raw Docker output14336 bytes, stdout8192 bytes, stderr4096 bytes, and at most256 records. Stderr is counted and discarded. Raw daemon bodies are privately projected and zeroed, never included in evidence. The shared multiplexer is unchanged; this module has a separate fixed probe stream reader because the worker stdout cap is smaller.

The genuine native input barrier runs before the challenge; its retained pidfd/proc/scope and live guard/endpoint/deadline checks run at every write and FIN. It receives no caller snapshot or authorization callback. The probe waits only one second for input, so the runner proceeds immediately after START and the native barrier, without an operator pause. Any mismatched actual facts refuse; this slice does not widen production FD/mount rules to accommodate the probe.

The private `probeJobs` completion state is separate from `decodedJobs`. Only ordinary mode, real BEGIN+FINAL+EOF, FINAL `COMPLETE/NORMAL`, WAIT0 and the original live lease/deadline can mark probe completion. `finishSettledControlProbe(jobId)` additionally requires the exact settled CREATE/START, closed admission barrier, matching terminal INSPECT, no OOM, whole-parent native empty, non-force owned REMOVE204, exact-ID absence and fresh whole-parent re-empty. Private Engine receipts are minted in the same broker process. A distinct cleanup schema is checked against the stored tagged request. `FINALIZED` means capacity was released; it does not mean any security control passed. The worker cleanup method still requires its original private worker completion state.

## Explicit invocation and evidence

Root must stage and verify the complete source/addon/profile closure and start the independent guard beforehand. Guard and broker must use the same addon SHA because it participates in the parent binding. No source-side fixture may substitute for a genuine Linux object.

Invoke `node scripts/qualify-proof-decoder-control-probes.mjs /absolute/protected/config.json` on the approved target only. The root-owned closed config contains exactly `schema: atlas-proof-decoder-control-probe-operator-v1`, `plan`, `addonPath`, `addonSha256`, `expectedBootId`, `epoch`, one `mode`, and a new `evidenceDirectory` under protected root-owned ancestors. The script requires Linux, Node22.16.0 and UID/GID0. It generates the request UUID and fresh nonce itself, creates one new ledger and never accepts ownership/reopen tokens.

The script saves the durable reservation before effects and a bounded final receipt. It deliberately closes the guard after its one probe, freezing/quarantining that epoch even after a successful normal settle. The receipt distinguishes terminal state from after-shutdown state. Neither JSON field revives a private receipt brand. It contains no environment enumeration, credentials, raw Config.Env, unbounded stderr or arbitrary error message. `workerValidation` is always null, `controlAcceptance` is `NOT_EVALUATED`, and `runtimeQualified`/`freshPublicationAllowed` remain false.

Independent root observations must join the actual mode/challenge/job/boot/parent/container and original deadline with effective kernel resource state and counters, errno interpretation, actual OOM events or independently timed guard death/freeze/empty. Probe self-reports alone cannot establish those controls. See `PROOF_DECODER_CONTROL_PROBES.md` and the 22-case design for uncovered syscall/control subvariants. Local pure parser/refusal tests establish no positive native transport, process, image or security-control behavior.

## Faults and reconciliation

`MEMORY_OOM` and `CPU_DEADLINE` deliberately cannot produce normal completion. Missing FINAL/EOF, STOPPED, unexpected success, malformed output, deadline, cancellation, guard loss or uncertain CREATE/START/REMOVE poison the epoch and freeze/kill the parent. The exact pending intent, identity and writer lock remain held. A valid BEGIN prefix is retained as a claim; later OOM/death evidence does not synthesize FINAL, WAIT, successful cleanup or worker validation.

This slice has no thaw, latch clearing, reset, unlock, delete-ledger, replacement-registry recovery, retry, arbitrary cleanup endpoint or service management path. Its creation of a fresh registry is only the initial one-shot run under an already healthy guard and genuinely empty parent; it cannot adopt or recover a fault epoch.

Before a later normal epoch, the operator must separately verify the same boot/parent identity, immutable prior receipt, full current FINALIZED row and metadata, all settled operation identities, known WAIT, exact absence, zero remaining containers, empty/frozen parent, stopped guard and exact prior latch. Root may then perform an explicitly reviewed archival/reset action outside this runner.

A poisoned ledger remains held and immutable. Even a known owned process fault with settled CREATE/START requires a separately reviewed operator reconciliation of actual WAIT/terminal state, frozen whole-parent emptiness, settled effects and exact non-force removal/absence. Such an external record never changes the old row to FINALIZED or rebrands JSON. Unknown CREATE/START cannot be resolved by name lookup, a404, timeout or a single empty snapshot; no thaw/new epoch is permitted from those observations alone. Command settlement and host quiescence require external investigation. No part of that recovery is implemented here.
