# Decoder source contracts — unqualified

The profile and target-evidence modules describe a prospective Linux/Docker decoder boundary. They do not build an image, execute a command, open a socket, inspect a host, decode bytes or grant an existing marketplace capability. The current proof validator, physical factory and proof intake remain unchanged. Worker, supervisor, independent watchdog and accepted-capability integration require separate review and implementation.

`createProofDecoderLaunchPlan({enabled:false})` returns null. Explicit `enabled:true` requires the complete profile; there are no target defaults. It returns an immutable `UNQUALIFIED` plan with `executionAllowed:false`, profile and limits hashes, and structured `createArguments` tokens. No shell string or process invocation exists. `assertProofDecoderLaunchPlan` recomputes that exact source structure; it does not brand a runtime capability.

Required profile inputs are the target reference, digest-pinned image, Linux architecture, explicit Node 22 version, nonroot worker UID/GID, four existing image limits, finite resource bounds, seccomp path/hash, enforcing MAC policy expectation, IPC identity/path expectations, and worker/dependency-lock/supervisor/watchdog source hashes. Missing facts refuse. The image layout and command are authored source expectations, not claims that those paths or any image exist. Caller commands, extra arguments, arbitrary environment, host mounts, devices, published ports, Docker endpoints and unknown keys are rejected. Node 22, sharp 0.33.5 and libvips 8.15.3 preserve the existing decoder closure expectation; Linux compatibility still needs actual evidence.

The plan fixes read-only root, private IPC/cgroup namespaces, network none, dropped capabilities, no-new-privileges, no image pulling, no automatic restart and no persistent container log driver. It specifies a memory cap with total memory-plus-swap equal to memory, CPU quota, PID/thread cap, descriptor/core limits, and separately bounded `/tmp` and `/dev/shm`. Native memory, thread counts, allocation pressure and timing must be observed on the eventual target; a finite requested limit is not proof that it was enforced or sufficient. The 128 MiB V8 heap option is not a native allocation boundary. Resource values in tests are fabricated schema examples, not recommended deployment sizes.

The worker may have no operator-added host/data volume or image-declared volume. This does **not** mean Docker has no mounts: generated `/proc`, `/dev`, `/sys`, hosts/resolver/hostname files and the two bounded temporary mounts must be enumerated and qualified in the actual mount manifest. `observed.mountManifestSha256` binds the retained enumeration; `operatorAddedMounts:[]` alone cannot establish isolation. The target tests must verify that application secrets, private proof storage, other jobs, host authority and the Docker socket cannot be accessed. The unsafe worker receives only bounded bytes/metadata through attached streams; the IPC directory is shared between app and supervisor, not mounted into the worker.

Image-defined environment and runtime environment are separate observations. The chosen image must actually have no baked-in ENV entries, including inherited entries. The runtime map must match the five fixed HOME/HOSTNAME/PATH/UV_THREADPOOL_SIZE/VIPS_CONCURRENCY entries; declaring an empty image ENV does not prove this. Neither the application environment nor secrets may be forwarded. No arbitrary image is safe merely because its name includes a digest.

IPC policy requires an explicit Unix-socket path and separate supervisor/client UIDs. The contract expects a supervisor-owned directory at 0750, a supervisor-owned socket at 0660, both using the client group, protected ancestors, no symlinks and no client ability to replace the endpoint. Claimed device/inode values, peer PID/UID/GID and service epoch are retained. The future qualifier must measure these facts, inspect supplementary groups/ACLs and prevent path/peer replacement across connection and readiness checks. This stage reads neither the filesystem nor peer credentials.

`assessProofDecoderTargetEvidence({plan,evidence,now})` checks the exact document schema, profile/limits/artifact agreement, explicit validity interval, claimed runtime/IPC/resource observations, mount-manifest and corpus/harness digests, and the 22 required adversarial case entries. Case results are PASS, FAIL or NOT_RUN with bounded observation references; missing/duplicate cases refuse. Failed and unrun cases remain explicit. Even a complete all-PASS document returns **UNVERIFIED**, `runtimeQualified:false`. `contractComplete` means the caller supplied internally consistent claims for all required cases, not that their claims are true or approved. No signature, trusted key, host observation or qualification authority is verified here. A plan hash is not a qualification hash. Existing `assertProofImageValidator` rejects both plans and assessments.

The case contract covers valid PNG/JPEG full decode, input/pixel bounds, corrupt/truncated/appended files, forged/duplicate/trailing output, external-network denial, host/private-data denial, read-only root/code, privilege/namespace denial, cross-job access, native OOM, CPU/wall deadlines, PID/thread/FD/tmpfs/shm exhaustion, cancellation with ignored termination and descendants, app death/disconnect, supervisor death with independent watchdog, restart reconciliation, uncertain cleanup quarantine, epoch/profile tamper, concurrency/no queue, and IPC peer/directory integrity. Each future observation artifact must contain the exact probe, target identity, start/end times and measured outcome; this module does not inspect those artifacts.

Future terminal cleanup evidence must come from the trusted supervisor/watchdog, not the unsafe decoder. Socket closure, client timeout and `--restart=no` do not prove worker death. Slots remain unavailable while cleanup is unknown. On the selected cgroup-v2 target, the supervisor must observe the complete owned descendant hierarchy empty, preserve exit/OOM/cleanup evidence before removal, and reconcile previous-generation jobs before advertising a new epoch. Failure to observe bounded cleanup keeps admission disabled. No unknown job is automatically replayed.

Official references for the proposed controls: [Docker run options](https://docs.docker.com/reference/cli/docker/container/run/), [resource constraints](https://docs.docker.com/engine/containers/resource_constraints/), [network none](https://docs.docker.com/engine/network/drivers/none/), [seccomp](https://docs.docker.com/engine/security/seccomp/), [tmpfs](https://docs.docker.com/engine/storage/tmpfs/) and [Linux cgroup-v2](https://docs.kernel.org/admin-guide/cgroup-v2.html). The target must independently demonstrate support and enforcement. Docker network none retains loopback; default seccomp is not a proof of complete syscall isolation; tmpfs can count against memory and needs the separate no-swap observation.

Focused local evidence: the two new profile/qualification test files pass 10/10 on pinned Node 22.16.0. They exercise source contracts and explicitly synthetic documents only. No container, target OS, image, secret, endpoint, UID, reviewer fact or actual containment qualification has been supplied. No provider, financial, label, production or shared-host effect was performed.
