# Concrete target input barrier

The target-only transport must obtain a live kernel input barrier before writing even the PDW1 header. The existing executor still performs START, then running INSPECT, then `sendOriginal()`. Unjoined fixture transport remains unqualified and does not acquire this target barrier. The target path has no bypass switch or caller-supplied observation/callback.

`controller.openWorkerInputBarrier({pid,containerId,plan,deadlineBootNs})` uses the genuine controller's retained parent and a new native asynchronous operation. The Engine PID is only a selector: a retained pidfd, pinned proc directory and exact `docker-<full-id>.scope` bind observations to the current owned worker. The operation uses N-API asynchronous work; the broker event loop continues sending guard heartbeats. It retains read-only parent/scope handles and never enters namespaces, attaches a tracer, signals a PID, reads environment files, or reads target file-descriptor contents.

The closed policy requires the fixed Node executable/argv, all real/effective/saved/filesystem UID/GID values from the plan, no supplementary privileged group, all five capability sets zero, no-new-privileges, seccomp filter mode with the observed count of one, exact named AppArmor enforce label, and separate PID/IPC/network/mount/cgroup namespaces versus host PID1. Each bounded task must agree; the user namespace is reported separately and may equal the host. It checks exact leaf memory/swap/CPU/pids values, no OOM event, one worker process, nofile/core limits, loopback-only interface names and a closed realized mount inventory. The mount policy follows this target's actual bootstrap inventory, including the readonly root, readonly Docker metadata files and kernel masks. Unknown mounts refuse; overlay superblock `rw` does not negate the required per-mount root `ro`.

Descriptor metadata is limited to 64 entries. Stdio must be pipes with the proper access mode. Further descriptors must be close-on-exec pipes, eventpoll/eventfd, the worker's `/dev/null`, or readonly exact pre-input module files whose inode matches the pinned worker root. Sockets, directories, unknown paths, mismatched root inodes and writeable source handles refuse. Unknown target links refuse before any target dereference. For the finite permitted target kinds only, metadata is checked against fdinfo inode/mount ID using stat/statx, then target/flags/inode/mount/metadata are reread and must agree. No file contents are read through target fd magic links. These consistency checks are not an atomic snapshot against an adversarial FD-table ABA swap; the pre-input process is the exact reviewed worker before caller bytes, and no such adversarial atomicity is claimed. Native task/fd sets are bounded and must stay identical across the collection. No rule is broadened merely because a runtime attempt fails.

The native operation retains the pidfd and descriptors after collection. The returned barrier exists only inside the concrete controller closure; it checks current parent/scope membership, process lifetime, executable and namespace identities immediately before every write and FIN. `sendOriginal()` closes it on success, failure and transport close. The original absolute CLOCK_BOOTTIME deadline is unchanged. A failed or unavailable observation releases no input and follows existing executor/ledger quarantine and independent freeze/kill behavior. Active collection is limited to one and resources are released on rejection or close.

Reads use fixed paths, bounded buffers and descriptor-relative operations. There are at most 32 tasks, 64 descriptors, 64 mount entries and 64 KiB of mount text. This bounds work and allocation, not a stalled kernel syscall: `O_NONBLOCK` is not a hard deadline for every kernel operation. The separate guard remains necessary; no claim is made that a JavaScript timer or native thread can replace it.

`reviewProofDecoderKernelWorkerControls` is a pure, explicitly UNQUALIFIED parser for tests and review. It never brands data or creates native handles. Serialized summaries cannot substitute for a live native barrier. The source remains default off and produces no runtime qualification, publication permission or ownership authority.

The kernel's seccomp mode/count does not prove equivalence of installed BPF instructions to the submitted JSON. Exact artifact submission, applied named AppArmor policy, hostile enforcement probes and final qualification remain separate evidence. This barrier also does not establish dynamic sharp/libvips mapping closure: the fixed worker imports sharp lazily after input, so that observation belongs to qualification after input. A control snapshot cannot establish immutability against a privileged host actor.

Validation is split: focused synthetic parser/refusal tests locally; root-only strict Linux compilation and actual before-input positive/negative checks against the new addon and pinned source; then independent hostile probes and the complete 22-case qualification. Local fixtures never stand in for kernel success. Appending an addon changes protected artifact pins and therefore requires fresh exact target plan/source bindings.

Primary interface references: [Linux proc documentation](https://docs.kernel.org/filesystems/proc.html), [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html), [pidfd_open](https://man7.org/linux/man-pages/man2/pidfd_open.2.html), and [mountinfo](https://man7.org/linux/man-pages/man5/proc_pid_mountinfo.5.html).
